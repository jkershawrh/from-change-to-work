# From change to work

The buyer is a manufacturing operations owner who needs engineering changes to become controlled, accountable work at an edge cell. The cell owner and engineering team jointly own the first acceptance decision. Aerospace inspection positioning provides a concrete setting; it is not a claim of aircraft inspection accuracy or production approval.

The hypothesis is that a repeatable handoff can reduce uncertainty and manual coordination when deploying an approved task and recovering from a failed delivery or executor. No factory baseline, savings, throughput or quality improvement has been measured. The first pilot must measure approved-release-to-admitted-task effort, manual handoffs, recovery effort and the verified task outcome against the site's existing process.

The trigger is one approved task change for one named cell. Central preparation defines a bounded capability and its receiving profile. Delivery carries the exact release. The local runtime admits only an approved compatible package, activates while idle and pins the task. The result retains its identity. A failed connection and a failed executor produce different, inspectable outcomes.

The proof transfers signed deterministic positioning recipes to MuJoCo through the existing Rust controller. It does not deliver a driver, trained model, defect detector or arbitrary robot code. Inspection positioning and rework positioning reuse the same implementation. Machine tending and other modules are opportunities requiring reviewed adapters, not implemented product features.

Intel and Red Hat are the target compute/platform partnership. Retained separate-host evidence used Intel Xeon processors, RHEL containers and OpenShift. That is historical simulator evidence, not certification, accelerator benchmarking, a new host qualification or physical robot acceptance. The reusable delivery contract is hardware-independent within each admitted profile; device integration remains explicit.

The pilot decision is to qualify one task on named central and edge hosts with an acceptance owner. Continue only when the scoped evidence supports the agreed task outcome and recovery behavior. Keep production-value evidence separate from software checks. A physical pilot additionally requires a reviewed OEM interface/adapter, tooling/calibration, safeguarding and local acceptance.
